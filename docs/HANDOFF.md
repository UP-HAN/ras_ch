### 주의할 점

- 서버(Lightsail, `ssh ras-server`)의 다른 앱(class-backend, class_tool DB, 다른 nginx 사이트)은 절대 건드리지 않는다.
- 서버에서 빌드하지 않는다(RAM 914MB). 배포 순서: 로컬 `npm run build` → `tar czf - server/dist client/dist | ssh ras-server "cd /var/app/<앱> && rm -rf server/dist client/dist && tar xzf -"` → 서버에서 **`git pull`**(마이그레이션 .sql 은 dist 에 없다) → `npm run db:migrate` → `pm2 reload`. 의존성이 바뀌었을 때만 `npm ci`(`--omit=dev` 쓰면 마이그레이션용 tsx 가 빠진다).
- **사용자 상시 지침(2026-10-06): 기능을 만들면 항상 커밋하고 운영·시연 두 사이트에 모두 배포한다.** 운영 반영 전 백업을 한 번 만든다.
- **복원 중에는 배포하지 않는다.** 화면이나 `node server/dist/ops/backupCli.js list` 에서 진행 중인 작업이 없는지 먼저 본다.
- 백업 폴더는 인스턴스별로 따로: 운영 `/var/backups/ras-point/points`, 시연 `/var/backups/ras-demo/points`. 두 `.env` 원본은 `.env.bak-20261006` 로 남겨 둠.
- 시연 사이트 "마지막 복원" 칸에는 2026-10-06 실패 훈련(손상 백업 거부) 결과가 실패로 표시되어 있다. 정상이다.
- `.env`(로컬·서버)와 SSH 키는 git 에 없다. 새 컴퓨터는 `docs/SETUP-NEW-PC.md` 참고. 로컬 `.env` 에 `BACKUP_DIR`·`MYSQL_BIN_DIR` 를 넣으면 이 PC 에서도 백업·복원을 시험할 수 있다.
