# 월간 결산(settlement) 모듈 설계 메모

PRD: HOF-02, 02a, 02b, 02c, 03, 04, 05, 08 / 7.2~7.4 / TASKS 5-2, 5-3

## 원칙

1. **산식 함수는 DB를 모른다.** `loadInputs.ts` 한 곳에서 원장·게시글·출석을 집계해 `types.ts`의 입력 배열을 만들고, 각 산식 함수는 배열 → 배열이다. 테스트는 픽스처 JSON으로 DB 없이 돈다.
2. **결과는 스냅샷 테이블에 불변 저장**: `monthly_settlements`(초안/확정), `monthly_scores`(학생별 포인트·성장률·선정·넘김 사유·동점 근거), `monthly_class_scores`(반별 평균·참여율·순위·학급 보상), `monthly_awards`(3부문 후보·선정). 화면은 스냅샷만 읽는다.
3. **연속 선정 제한**은 `monthly_settlements.prev_settlement_id`로 지난달 스냅샷을 읽어 판단하고, 넘긴 사실은 `skipped_reason`에 남긴다(승인 교사가 예외 허용 가능).

## 파일 배치 (S5에서 채움)

| 파일                      | 역할                                                                                                 | 구현 순서 |
| ------------------------- | ---------------------------------------------------------------------------------------------------- | --------- |
| `loadInputs.ts`           | 원장·게시글·출석·동의 집계 → `StudentMonthInput[]`, `ClassMonthInput[]`, `PriorWinners`              | 1         |
| `monthlyTop.ts`           | 학년별 포인트 상위 N명(동점: 리포트 > 기사 > 활동 일수 > 공동), 주간 수령자 제외 토글                | 1         |
| `awards.ts`               | 7.2 실천왕 / 7.3 기자 / 7.4 참여왕 점수·근거, 학년별 상위 5명, 중복 경고                             | 2         |
| `classReward.ts`          | 반별 평균(미동의 제외) 1위, 동점 시 참여율                                                           | 3         |
| `growth.ts`               | (이번 달 − 지난달) ÷ 지난달, 자격: 지난달 ≥ 30P & 이번 달 ≥ 학년 중앙값, 상위 5명 제외, 첫 달 미운영 | 4         |
| `consecutiveLimit.ts`     | 지난달 선정자·반을 다음 순위로 넘기고 `skippedReason` 기록                                           | 5         |
| `draft.ts` / `confirm.ts` | 초안 생성(매월 1일 00:05 배치) / 확정 시 MONTHLY_TOP·GROWTH_AWARD·MONTHLY_AWARD 지급 + 알림          | 1 / 1     |

순서 4·5(성장률·연속 제한)는 PRD 15장 오픈 이슈대로 일정이 빠듯하면 2차로 미룰 수 있다. 스키마는 이미 갖춰져 있어 미뤄도 마이그레이션 변경이 없다.
